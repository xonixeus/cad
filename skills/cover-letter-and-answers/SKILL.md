# Cover Letters and Application Answers

## When to use

- Scribe: drafting a cover letter or answers to application questions for a role the client is pursuing.
- Watson: advising on the messaging or reviewing a draft's strategy.

Documents start only after the client says they will pursue the role (`cad:TEAM.md` §10).

## Before you start

1. The posting analysis (`job-posting-analysis`) and, for employer-specific content, a company brief (`company-research`).
2. `client:knowledge/CLAIMS_LEDGER.md` (only Verified, Use `Resume` claims, within Limits) and `POSITIONING.md`.
3. Profile alignment (`profile-alignment`) when the posting stresses values or culture.
4. The tailored resume, if one exists, so the letter and resume tell the same story without repeating it.

## Cover letter

- **Length:** 250–400 words, three to five short paragraphs, unless the posting asks otherwise.
- **Opening:** the role, and the single strongest reason the client fits it, specific to this employer. No "I am writing to apply for…".
- **Body:** two or three points that match the posting's core requirements, each backed by a Verified claim (cite IDs in the note, not in the letter). Add one genuine, sourced connection to the employer (mission, product, recent news) when it exists.
- **Close:** what the client would bring, and an invitation to talk. No pleading, no generic praise.
- Address a named hiring manager only if the name is public and verified; otherwise use a neutral salutation.
- Voice: first person, matching the client's communication preferences and `CONTEXT.md` where it helps; never invent anecdotes.

## Application answers

- Answer exactly what is asked, within any character or word limit (state the count).
- Behavioral questions: situation, task, action, result, built only on Verified claims.
- Eligibility questions (work authorization, salary expectations, notice period, relocation): use only what the client has recorded. If it is not recorded, leave a placeholder and ask; never guess.
- "Why us?": specific and sourced, never flattery.

## Output

The draft plus a short note: target, sources used, claim IDs per paragraph or answer, Pending facts left out (as questions), and word counts. Name and hand off per `document-handoff`. These documents always need the client's approval before use.

## Stop and ask

- A question asks for information the client has not recorded.
- The strongest available story depends on a Pending claim.
